# 한컴 오라클 채굴 2차 — 저장 line_seg 전수 + 한컴 PDF 벡터 실측 (2026-08-06)

선행: [`oracle-corpus-mining-20260805.md`](oracle-corpus-mining-20260805.md),
[`tac-inline-baseline-report-20260805.md`](tac-inline-baseline-report-20260805.md),
`mydocs/report/layout_physics_20260805.html` §7.

대상 질문 2건 — ① end-anchor 글자취급 표의 "자기 줄" 규칙이 실재하는가, ② 표+글 공유
줄의 baseline 비율(0.85 vs 0.5)이 무엇에 의존하는가.

방법: `samples/` 재귀 656파일(hwp+hwpx, 파싱 실패 0)을 임시 example 로 순회 —
본문·셀(중첩)·글상자(묶음 재귀)·머리말/꼬리말·각주/미주 문단 전부에서 글자취급 표를
찾아 `control_text_positions()` 로 표의 char/utf16 위치를 확정하고, 저장
`line_segs`(text_start·vertical_pos·line_height·text_height·baseline_distance·
line_spacing·column_start·segment_width·tag)를 덤프. 표 위치는 `char_count` 와
`char_offsets` 로 교차검증(컨트롤 8 code unit + 문단끝 1). 한컴 인쇄 PDF 는 컨텐츠
스트림을 zlib 해제하고 CTM(`q`/`Q`/`cm`)을 추적해 `re`/`m`+`l` 벡터와 텍스트 기준선
(`Tm`/`Td`/`T*` → `Tj`/`TJ`)의 절대 좌표를 뽑아 대조. 단위: HWPUNIT(7200/inch),
PDF 는 pt(=100HU). 임시 example(`examples/oracle_q1q2_scan.rs`)은 삭제했다.

## 질문 1 — end-anchor 표의 "자기 줄" 규칙: **저장 인코딩과 어긋난다 (반증)**

### 1-A. 앵커 유형별 전수 집계 (글자취급 표 5,751건)

| 유형 | 정의 | 건수 | 표가 든 seg 에 가시 텍스트 동거 |
|---|---|---|---|
| SOLO | 문단에 표만 (앞뒤 가시 텍스트 없음) | 5,672 | 0 |
| START | 표 뒤에만 가시 텍스트 | 30 | 18 |
| **END** | **표 앞에만 가시 텍스트** | **25** | **8** |
| MID | 앞뒤 모두 가시 텍스트 | 24 | **24 (전부)** |

"가시"= 공백·PUA(U+E000–F8FF)·제어문자 제외.

**결론 1-B: END-anchor 이면서 "폭이 남고 `\n` 도 없는" 표본은 전부 seg 1개다. 즉
한컴 저장 인코딩에 "end-anchor 표 = 자기 줄" 시멘틱은 없다. 2개 이상인 표본은 100%
폭 초과 또는 강제 줄바꿈으로 설명되어, 1차 채굴의 횡단 법칙 3("전부 폭 기준 줄바꿈의
귀결")이 END-anchor 축에서도 그대로 성립한다.**

### 1-C. 폭 임계 시리즈 — `tac-case-001..005` (같은 문단, 표 폭만 다름)

MID-anchor 이지만 "표가 앞 텍스트와 같은 줄에 남는가"를 직접 재는 대조군이다.
문단은 5파일 모두 동일: `text="tacglkj 표 3 배치 시작    4 tacglkj 표 다음"`,
표는 `pos=19`(가운데), sw=42520, 표 높이 2568 + 바깥여백 566 = 글리프 3134.

| 파일 | 표 폭 | 저장 segs | 줄 구조 |
|---|---|---|---|
| `tac-case-001.hwp` s0#1 | 13554 | **1** | 앞 텍스트 + 표 + 뒤 텍스트 전부 한 줄, lh=3134 bd=2664 (0.8500) |
| `tac-case-003.hwp` | 24874 | 2 | 앞 텍스트+표 = 줄1(lh=3134), **뒤 텍스트만** 줄2(lh=1000) |
| `tac-case-004.hwp` | 25440 | 2 | 같음 |
| `tac-case-002.hwp` | 27138 | 2 | 같음 |
| `tac-case-005.hwp` | 28836 | 2 | 같음 |

표가 넓어질 때 다음 줄로 밀리는 것은 **뒤 텍스트**이고, 표는 끝까지 **앞 텍스트와 같은
줄**에 남는다. 현행 엔진의 end-anchor 규칙(앞 텍스트는 위 줄, 표는 아래 줄)은 이 시리즈와
상하 반대 방향이다. MID-anchor 24건도 24건 전부 표가 텍스트와 같은 seg 에 있다.

### 1-D. 한컴 PDF 실측 — 표와 텍스트가 **한 줄에 렌더된다**

END-anchor 고신뢰 3문서에는 짝 PDF 가 없다(**해당 축의 PDF 표본 부재**). 대신 짝 PDF 가
있는 유일한 "표+글 동거 seg" 표본으로 렌더 y 를 실측했다.

`samples/복학원서.hwp`(=`.hwpx`) s0#16 / `samples/복학원서.pdf` (Hancom PDF 1.3.0.404, 1쪽 595×841pt)

저장: 표 w=48184 h=21016 바깥여백 좌우 280·상하 280(각 변 140), sw=51592.
segs = `{ts=0 vp=55288 lh=1000 th=1000 bd=850 ls=600}`,
`{ts=198 vp=56888 lh=21296 th=21296 bd=18102 ls=720}` → 문단 = 필러 99자 / 표 / 필러 2자,
표는 utf16 [198,206) 로 **2번째 줄의 첫 항목**, 그 줄에 뒤 필러 2자가 동거.

PDF 실측:

| 측정 대상 | 실측 | 저장 seg 로부터의 예측 | Δ |
|---|---|---|---|
| 표 테두리 x | 43.90 … 525.44 (span 481.54) | 폭 481.84 − 선폭 inset | 0.3 |
| 표 테두리 y | 33.08(아래) … 243.09(위), h=210.01 | 높이 210.16 − 선폭 inset | 0.15 |
| 줄1 필러 기준선 | **y=251.96** (x 42.46…553.02, 폭 515.7 ≈ sw 515.92) | 244.49+16.00−8.50 = 251.99 | **0.03** |
| 줄2 뒤 필러 2자 기준선 | **y=63.65** (x=526.87, 531.91) | 244.49−181.02 = 63.47 | **0.18** |

(예측의 줄2 상단 = 표 테두리 위 243.09 + 바깥여백상 1.40 = 244.49. 줄1 상단은
vp 차 1600HU=16.00pt 위, 기준선은 bd 850HU=8.50pt 아래.)

→ **표 오른쪽 x=526.87 에 뒤 필러 2자가 표와 같은 기준선 줄에 렌더된다.** 한컴 인쇄
결과에서도 글자취급 표는 같은 줄의 글자와 동거한다. 줄1 이 따로 있는 이유는 필러
99자(510.6pt) + 표(481.8pt) ≫ 줄폭 515.9pt 라는 **폭** 이며, 폭이 남는 2자는 표 옆에 남았다.

### 1-E. 1차 채굴/웹한글 실측과의 상충 (덮어쓰지 않고 명시)

- `tac-inline-baseline-report-20260805.md` "한컴 오라클 채취 완료" 절의
  **"표 앞 텍스트는 표 위 줄, 표는 아래 줄"** 은 위 저장 코퍼스(고신뢰 3문서 + tac-case
  시리즈)와 PDF 실측 모두와 **정면 충돌**한다. 그 실측은 웹한글 편집 화면 픽셀 관찰이며
  같은 문단에서 나온 형제 주장("표가 텍스트보다 46px 위")은 뒤에 전혀 다른 원인
  (Table.attr 오설정, 96d24f4b3)으로 밝혀졌다. **재현 절차가 기록에 남아 있지 않고
  저장 파일도 채취되지 않아 재검증 불가** → 본 문서는 저장 인코딩 + 한컴 인쇄 PDF 를
  우선한다. (웹한글에서 같은 문단을 만들어 **저장한 .hwp/.hwpx** 를 채취하면 최종 종결.)
- 1차 채굴의 횡단 법칙 3 과는 상충 없음 — 오히려 END-anchor 축에서 재확증.

## 질문 2 — 공유 줄 baseline 비율: **표 구조가 아니라 문단 세로정렬 속성**

### 2-A. 0.85 / 0.5 의 정체 = 문단 모양 "세로 정렬"

저장 seg 전수(573,835개, lh>0·bd>0) `baseline_distance / line_height` 히스토그램:

| 버킷 | 0.50 | 0.85 | ≥0.95 | 그 외 |
|---|---|---|---|---|
| 개수 | 30,613 (5.3%) | **522,175 (91.0%)** | 1,116 | 19,931 |

문단 모양 `ParaShape.attr1` **bit 20–21(세로 정렬: 0=글꼴기준·1=위쪽·2=가운데·3=아래쪽)**
과 교차:

| bd/lh | attr1 bit20-21 = 0 (글꼴기준) | = 2 (가운데) | = 3 (아래쪽) |
|---|---|---|---|
| ≈0.50 | 32 | **30,336** | 0 |
| ≈0.85 | **508,624** | 3,467 | 0 |
| ≈1.00 | 870 (빈 꼬리말 등 bd=lh 축퇴) | 0 | **204** |

HWPX 교차검증 — `samples/hwpx/exam_social.hwpx` `Contents/header.xml` 의
`<hh:align vertical="CENTER">` 를 가진 paraPr id 집합 = {25, 40, 43, 48, 54, 63},
그 문서에서 bd/lh≈0.5 인 줄이 쓰는 paraPr id = {25, 40, 43, 48, 54} — **전부 CENTER**.
(BASELINE 66개 / CENTER 6개 / BOTTOM 1개.)

**질문에서 지목한 `samples/exam_science.hwp` s0#61 은 para_shape 102, attr1=0x00200000
→ 세로정렬 = 가운데.** 그래서 그 문단의 표 줄(lh=2864 bd=1432)도, 순수 텍스트 줄
(lh=1150 bd=575)도 똑같이 0.5 다. 같은 문서 안에서 세로정렬=글꼴기준인 문단
(예: s0#68/cell5#2, lh=2864 bd=2434)은 표를 품고도 0.85 다.

**결론 2-A: 0.85 는 문서(폰트·줄간격) 의존도 아니고 "표 자기 줄 vs 공유 줄" 구조 차이도
아니다. `bd = r × lh` 이고 r 은 문단 모양의 세로 정렬(글꼴기준 0.85 / 가운데 0.50 /
아래쪽 1.00)이다.** 1차 채굴의 "0.85 는 문서 의존일 수 있다"는 유보는 이로써 해소.
(잔여: 세로정렬=가운데인데 0.85 인 3,467건 — 미규명. HWPX→HWP 재파스 경로의 attr1
복원 차이 의심, **미측정**.)

### 2-B. 법칙 4("뒤 텍스트 baseline = 표 바닥") — **반증**

`samples/복학원서.pdf` 실측(1-D 표)에서:

- 표 잉크 바닥 y = **33.08**
- 같은 줄 뒤 텍스트 기준선 y = **63.65**
- 표 바닥은 기준선보다 **30.57pt(3057HU) 아래**.
- 예측식 `(1−r)·lh − 바깥여백하` = 0.15×212.96 − 1.40 = **30.54pt** → Δ 0.03pt.

즉 글자취급 표의 잉크는 기준선을 **가로지른다**. 뒤 텍스트 기준선은 표 바닥이 아니라
`줄상단 + 0.85×줄높이` 다. **법칙 4 는 성립하지 않는다.**

### 2-C. 글리프 상자 안 잉크의 세로 위치 (1차 채굴 "남은 미확정" 해소)

`samples/21_언어_기출_편집가능본.hwp` s0#0/cell6#0 + `…편집가능본.pdf`(1쪽 841.8×1191pt).
한 줄에 글자취급 표 2개: 성명(w=14174 h=2449, 바깥여백 566/566 → 각 변 2.83pt),
수험번호(w=21384 h=2448, 바깥여백 **0**). seg: lh=3015 bd=1507 (r=0.4998, 문단 세로정렬=가운데).

PDF 실측: 성명 잉크 x 220.44…362.52 · **y 966.48…990.96**, 수험번호 잉크
x 385.80…600.00 · **y 966.48…990.96** — **두 표의 잉크 y 가 완전히 동일**.

| 모델 | 예측 | 판정 |
|---|---|---|
| 잉크상단 = 줄상단 + 바깥여백상 | 두 표가 2.83pt 어긋남 | **기각** |
| 잉크바닥 = 줄바닥 − 바깥여백하 | 두 표가 2.83pt 어긋남 | **기각** |
| 글리프상자(잉크+바깥여백)가 기준선을 r:(1−r) 로 가름 | 성명 바닥 = 기준선+12.25, 수험번호 바닥 = 기준선+12.24 → 동일 | **채택** |

복학원서(r=0.85, 표가 줄높이를 정하는 경우)로 재검산: 글리프상자 상단 = 기준선+181.02
→ 잉크상단 = 그 −1.40 = 243.27(실측 243.09, Δ0.18), 잉크바닥 = **33.11**(실측 33.08,
**Δ0.03**). 잉크가 직접 기준선을 가르는 모델(바깥여백 무시)은 잉크바닥 32.13 → Δ0.95 로 열등.

**확정 관계식** (줄상단 기준 하향 y, `glyph_h = h + 바깥여백상 + 바깥여백하`, `r = bd/lh`):

```
잉크상단 = 줄상단 + bd − r·glyph_h + 바깥여백상
잉크바닥 = 잉크상단 + h
표가 줄높이를 정할 때(glyph_h == lh) → 잉크상단 = 줄상단 + 바깥여백상
```

주의(미측정): 두 표본 모두 바깥여백 상/하가 대칭(140/140, 283/283)이라 "글리프상자 가름"
과 "잉크 가름 + 대칭 여백" 을 이 자료만으로 완전히 분리하지는 못한다. 다만 복학원서의
Δ0.03 vs Δ0.95 는 글리프상자 모델을 지지한다.

> 정정(2026-08-06, (B) 적용 세션): 비대칭 바깥여백 표본은 **코퍼스에 있다** —
> `samples/exam_science.hwp`·`exam_social.hwp` 표지 셀의 TAC 표 3개가 om(상283/하0,
> h=2732, 줄 lh=3015 bd=2563 r=0.85)이다. 두 모델이 `바깥여백상 − r·(상+하)` =
> 283 − 240.6 = **42HU(0.57pt)** 갈린다. 그러나 두 파일 모두 **짝 PDF 가 없어**
> 판정은 여전히 미측정 — 현행 코드는 글리프상자 모델을 쓴다.

### 2-D. 곁가지 실측 — 가로 전진에 바깥여백이 **들어간다** (1차 채굴 정정과 상충)

1차 채굴 "정정(글리프 상자 세션)"은 `21_언어…` PDF 와 rhwp 렌더의 차분으로
"렌더 가로 전진은 잉크 상자(바깥여백 불포함)"라고 결론했다. 한컴 PDF **단독** 직접
실측은 반대다.

| 표본 | 표 잉크 우변 | + 바깥여백우 | 표 다음 글리프 원점 x | Δ |
|---|---|---|---|---|
| `복학원서.pdf` s0#16 표 | 525.44 | +1.40 = 526.84 | **526.87** | **0.03** |
| `21_언어….pdf` cell6#0 성명 표 | 362.52 (선폭 보정 362.35) | +2.83 = 365.18 | **365.16** | **0.02** |

잉크 전진 가설이면 각각 525.44 / 362.52 에서 다음 글리프가 시작해야 하고 Δ 는
1.4pt / 2.6pt 로 벌어진다. 1차 채굴의 결론은 두 렌더러의 **차분**(rhwp 가 1.11pt 넓음)
에 의존했고 그 안에는 공백 4자의 전진폭 차이가 섞여 있다(글리프상자 가설 하에서 4공백
= 20.64pt/5.16pt each, 잉크 가설 하에서는 23.62pt/5.90pt each — 문서 폰트 11.04pt 기준
전자가 자연스럽다). **본 문서는 상충을 기록만 하고 코드 변경을 권고하지 않는다** —
질문 범위 밖이며, 1차 채굴이 "고치면 회귀" 로 못 박은 축이므로 전용 검증
(rhwp 공백 전진폭을 한컴과 1:1 대조) 후에 판단해야 한다.
